Authority and permissions
Existing payroll entitlement, not a new commercial module.
Self read: employee.leave.view; request/upload: employee.leave.request;
cancel: employee.leave.cancel. Existing portal employee/me supplies employment
status under employee.self.view. If status cannot be verified, mutation controls
are unavailable while independently authorized leave reads remain usable.
Unlinked leave summary (409 EMPLOYEE_IDENTITY_NOT_LINKED) is explicit.
Resigned/terminated linked employees retain authorized history/holiday reads;
request, evidence upload and cancellation controls are absent.
Admin read/types/entitlements/evidence: leave.view. Type/allocation/adjustment:
leave.manage. Decisions: leave.approve. Holiday read/write: holiday.view/manage.
Admin page entry requires leave.view; its holiday panel additionally uses the
separate holiday permissions. Employee IDs are explicit administrative UUID
inputs, not a fabricated directory or self-identity selector.
Administrative decisions use is_own_request === false exclusively. Missing/null
ownership fails closed. No employee/me or user/employee/event matching determines
admin ownership. Backend self-approval enforcement remains final authority.

Units and workflow
allocated_units, adjustment_units, pending_units, approved_units, available_units
are displayed directly from the server. Integer presentation: 2 units = 1 day;
1 unit = 0.5 day. No client balance or requested-unit calculations.
FULL_DAY supports calendar date ranges. FIRST_HALF/SECOND_HALF require one date.
Server rejects past dates, overlap, insufficient balance and entitlement-year
violations. No weekend/holiday exclusions. Unpaid leave has no financial effect.
History uses server pagination and retains cancelled/rejected records.
Pending cancellation requires confirmation and records returned server state.
Approved future leave requests cancellation, followed by separate administrator
decision. Started approved leave has no cancellation control. Rejection requires
at least five characters. Conflict/uncertain decisions reload authoritative detail.

Evidence and privacy
Only private list/upload/download endpoints are used. Upload is available for
active employees' pending requests. UI extensions match certified configuration;
10 MiB is labelled the default, with configured server validation authoritative.
No remove/replace evidence API is invented. No storage paths, public links,
base64 persistence, HTML rendering, browser leave persistence, or fake notifications.
Downloads accept AbortSignal and do not emit files after an aborted context.
Sensitive forms/files/uncertain mutations clear on switch and component disposal.
Async reads are fenced by company, contextVersion, generation, per-channel
controller and component lifetime. Entitlement employee/year changes invalidate
outstanding reads. No payroll employee API, financial mutation, attendance
mutation, or other domain side effect is invoked by Leave.
Create and adjustment keys/payloads are retained in memory for uncertain retries.
No automatic retry of non-keyed decisions or uploads. Upload uncertainty prompts
refresh before another upload; decisions reload current state.
